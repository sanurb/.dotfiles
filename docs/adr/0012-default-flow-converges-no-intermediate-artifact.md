# ADR-0012: The default flow converges; no intermediate artifact

`dots install` previously had two modes. Inside a workspace it ran the full wizard and offered to realize. Outside a workspace it ran a form-only branch (`ModeStandalone`) that wrote a profile to `~/.config/dots/.dots-state.toml` and printed three manual steps for the user to perform: install Nix, clone the repo, run `dots deploy`. The default invocation on a fresh machine therefore terminated in a TOML file plus homework, not a configured system. Per Honesty (priority #1), a dotfiles manager whose default command stops at "now do these three things by hand" is mis-advertising its job.

This ADR retires the standalone branch. `dots install` is one path. When prereqs (Nix, workspace clone) are missing they are fulfilled in-flow under the same per-prereq Y/N consent contract `dots deploy` already uses (ADR-0010): each step prints the exact command before it runs; declining exits with code 2 and zero mutation. The wizard then runs against the now-present workspace exactly as it always did when the user was already inside one. The ModeStandalone enum, the `standalonePersister`, the `~/.config/dots/` state path, and the three-step epilogue are all deleted.

ADR-0001 is partially superseded. Its first clause — "two components, one product" — still describes the architecture: a Go binary and a Nix realization layer that don't import each other. Its second clause — "the TUI ships standalone so users can try the wizard without committing to Nix" — is no longer the design intent. The binary still ships standalone (Homebrew, curl-install, `nix run`); ADR-0011 made the curl path a peer of the others. What changes is the *behavior* of that standalone-distributed binary on a machine without Nix: it now bootstraps Nix (with consent) instead of producing a portable-profile artifact and stopping. The "try the wizard without committing to Nix" use case is real but power-user — it now lives in a future explicit `dots capture` verb, never in the default flow.

I1 holds. The bootstrap package's import set is unchanged (`os/exec`, `os`, `io`, `bufio`, `path/filepath`, `fmt`, `strings`); installing Nix and cloning the workspace remain subprocess invocations of `sh`, `git`, and the Determinate installer. ADR-0009's contract (TUI exits before realization; main.go re-invokes deploy as a subprocess) is preserved verbatim. ADR-0010's contract for `dots deploy` is preserved verbatim and is now mirrored in `dots install` so the two entry points share one bootstrap UX.

Trade-offs. (1) A user who genuinely wanted only the captured profile must wait for the explicit `dots capture` verb (Phase 2). (2) The Nix-just-installed re-run requirement still holds: the installer mutates shell rc files but not the current process's PATH, so `dots install` exits cleanly after the install with "open a new shell and re-run." That two-round-trip cost is the same one `dots deploy` already pays and is honest about. (3) The cached workspace lookup (`workspace.Root`'s `sync.Once`) is invalidated post-clone via a new `workspace.Reset()`; this is the only lifecycle hook in the package and is documented to be called by main.go alone. Alternative considered: refactoring `Root()` to be re-entrant by default. Rejected — the cache is correct for every other caller; a single Reset at one known sequencing point is cheaper than rethreading staleness through the API.

# ADR-0010: `dots deploy` self-bootstraps Nix and the workspace clone

`dots deploy` previously exited with code 2 and a copy-and-paste recipe when Nix or the workspace was missing. After ADR-0009 the install wizard auto-invokes deploy as a subprocess, which would have hit that same dead-end on a fresh machine. Bootstrapping in `dots deploy` itself, gated by explicit per-prereq consent, makes the install→deploy handoff complete.

The contract: at the start of `runDeploy`, detect Nix → detect workspace → run moon. Each missing prereq triggers a Y/N prompt that prints the EXACT command being offered (the Determinate Systems one-liner; `git clone <repo> <target>`). On Yes, the prereq is bootstrapped via subprocess and execution proceeds. On No, deploy exits with code 2; nothing is mutated. No silent execution.

The two prereqs differ in continuation. Workspace-just-cloned: dots `chdir`s into the clone and continues to moon — the new tree is reachable in the current process. Nix-just-installed: deploy exits with `Open a new shell and re-run \`dots deploy\` to continue.` because the installer mutates shell rc files but not the current process's PATH; trying to `nix develop` from the still-Nix-less PATH would fail. `DOTS_WORKSPACE` overrides the default `~/.dotfiles` clone target.

I1 holds: the bootstrap package's import set is `os/exec`, `os`, `io`, `bufio`, `path/filepath`, `fmt`, `strings`. Subprocess invocation of `sh`, `git`, and the Determinate installer is permitted under the import-vs-subprocess clarification recorded in ADR-0009. AGENTS.md §6 Distribution Model "Depth" remains accurate; the column "Requires Nix?" still reads Yes for the Full row, just delivered by consent rather than a precondition error.

Alternatives considered: re-execing `nix develop -c dots deploy` after Nix install (rejected — current process's PATH never sees the new nix binary); bundling Nix with the dots binary (rejected — the curl/Homebrew distribution explicitly wants Nix-free fallback). Doctor stays read-only and does not auto-bootstrap; it reports findings. The trade-off is one extra round-trip (install → re-run) for first-time users, which is honest about the PATH refresh requirement instead of pretending it doesn't exist.
